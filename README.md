## ✦ Overview

**Lord Vault** is a modular automation and utility framework designed for development, controlled testing, workflow automation, account-management experiments, connectivity checks, and internal tooling.

The project combines:

```text
┌──────────────────────────────────────────────┐
│                LORD VAULT CORE               │
├──────────────────────────────────────────────┤
│  Automation Engine                           │
│  Mail Provider Integrations                  │
│  Proxy Management                            │
│  Profile Configuration                       │
│  GUI + Terminal Interface                    │
│  Worker System                               │
│  Network Utilities                           │
│  Logging & Monitoring                        │
└──────────────────────────────────────────────┘
```

> Use Lord Vault only in environments where you have permission to perform automation or testing.

## ✦ Configuration

Lord Vault can be configured through:

```text
config.json
```

or through the GUI / terminal interface.

Example:

```json
{
  "mail": {},
  "proxy": {},
  "workers": {},
  "profile": {},
  "logging": {},
  "network": {}
}
```

---

## ✦ Proxy Support

Supported formats:

```text
ip:port
```

or:

```text
user:password@ip:port
```

Place proxies inside:

```text
input/proxies.txt
```

Example:

```text
127.0.0.1:8080
username:password@127.0.0.1:8080
```

---

## ✦ Worker Settings

Example:

```json
{
  "workers": 1
}
```

Higher concurrency may increase:

```text
CPU usage
RAM usage
Network usage
Provider requests
API usage
Rate-limit pressure
```

Start with a low worker count while testing.
